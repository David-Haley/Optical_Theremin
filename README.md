# Optical Theremin

Firmware for a Raspberry Pi Pico W optical theremin. Two ST VL53L0X
time-of-flight sensors measure the distance to your hands: one sets the
pitch of a DDS (direct digital synthesis) tone generator, streamed over I2S
to a PCM5122 DAC, and the other sets the DAC's volume.

- **Pitch** runs from 55 Hz (A1) at 360 mm to 1760 Hz at 60 mm, one octave
  per 60 mm. With no hand in range it plays the lowest note.
- **Volume** is loudest (0 dB) at 100 mm or nearer and falls 0.5 dB per mm
  to -103 dB at 306 mm. From 307 mm, or with no hand in range, it is muted.
- **Waveform** is chosen by grounding one of four inputs: `Sine`, `Sine_2`
  (a sine with second-order, vacuum-tube style distortion), `Triangle` or
  `Square`. With none grounded it plays `Sine`.

Both sensors are read 20 times a second. Rather than jumping at each
reading, the pitch glides to its new value over about 46 ms and the volume
over 50 ms (in 2 ms steps), so the sound follows the hands smoothly.

## Hardware

- Raspberry Pi Pico W
- Two ST VL53L0X time-of-flight distance sensors
- PiFi DAC+ V2.0 (TI PCM5122), which needs its own power supply (3.3 V and
  5 V on its Pi-style header). No master clock is needed: the DAC's PLL
  runs from BCK.

| Signal | Pico pin | GPIO | DAC header pin |
|---|---|---|---|
| Pitch VL53L0X SDA / SCL | 1 / 2 | GP0 / GP1 | — |
| PCM5122 SDA / SCL | 4 / 5 | GP2 / GP3 | 3 / 5 |
| Volume VL53L0X SDA / SCL | 4 / 5 | GP2 / GP3 | — |
| I2S BCK | 26 | GP20 | 12 |
| I2S LRCK | 27 | GP21 | 35 |
| I2S DIN | 31 | GP26 | 40 |

| Select Sine / Sine_2 | 14 / 15 | GP10 / GP11 | — |
| Select Triangle / Square | 16 / 17 | GP12 / GP13 | — |

The volume sensor shares the DAC's I2C bus. BCK and LRCK must be on
consecutive GPIOs (LRCK = BCK + 1). The waveform select inputs have internal
pull-ups; connect one to ground to select it.

## Building

Requires the [Raspberry Pi Pico SDK](https://github.com/raspberrypi/pico-sdk)
and the `arm-none-eabi` toolchain. Set `PICO_SDK_PATH` to point at your SDK
checkout, then:

```bash
mkdir -p build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release
cmake --build . -j$(nproc)
```

This produces `build/optical_theremin.uf2`.

If your installed `picotool` is older than the version this SDK checkout
requires, add `-DPICOTOOL_FORCE_FETCH_FROM_GIT=1` to the `cmake` configure
step to have it built from source automatically.

## Flashing

With [picotool](https://github.com/raspberrypi/picotool) installed:

```bash
picotool load -f -v -x build/optical_theremin.uf2
```

`-f` forces the board to reboot into BOOTSEL mode for the load even if it's
currently running application code, and reboots it back into the application
afterward. Alternatively, hold BOOTSEL while plugging in the Pico and drag
the `.uf2` file onto the `RPI-RP2` USB drive that appears.

## Usage

Once flashed, the theremin plays as soon as the DAC is initialised. The
board's USB serial port (e.g. `/dev/ttyACM0` on Linux, any baud rate) shows
start-up and error messages only:

```
Initialising Pitch VL53L0X...
Pitch factory range offset -16000 um
Pitch VL53L0X ready
Initialising Volume VL53L0X...
Volume factory range offset 46500 um
Volume VL53L0X ready
Waveform Sine
Initialising PCM5122...
PCM5122 running
Pitch out of range (status 4)
```

Sensor problems are printed when they change, e.g. `Pitch out of range
(status 4)` when the hand leaves the sensor's range, and the waveform is
printed when it changes. If the DAC fails to start, its
clock and power registers, an I2C bus scan, or the I2S pin activity are
printed to help find the fault.

## Project layout

- `src/main.c` — application entry point: sensor and DAC initialisation and
  the 20 Hz measurement loop, and the volume ramp.
- `src/dds_generator.c` — the DDS tone generator and pitch ramp.
- `src/dds_generator.h`, `src/dds_table.h` — generated by the Ada
  configuration tool (`src/optical_theremin.adb`); don't edit by hand.
- `src/audio_i2s.pio`, `src/i2s_output.c` — the I2S output (PIO and DMA).
- `src/pcm5122.c` — PCM5122 DAC set-up and volume over I2C.
- `src/waveform_select.c` — the waveform select inputs.
- `Api/core/` — ST's manufacturer VL53L0X API (ranging/calibration
  algorithms), unmodified.
- `Api/platform/` — the porting layer connecting the vendor API to the Pico
  SDK's `hardware_i2c` driver.
- `Documents/` — datasheets and design notes.

See `CLAUDE.md` for more detailed build/architecture notes, including how to
regenerate the DDS tables.
